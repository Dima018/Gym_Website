# REST API «Ритм» — КП №2

Base URL: `http://localhost:3000/api`. JSON UTF-8. Час зберігається в UTC.
Захищені запити: `Authorization: Bearer <token>`. Токен повертається після реєстрації / входу та діє 3600 секунд.

## Ендпоінти

| Метод | URL | Доступ | Результат |
|---|---|---|---|
| GET | `/health` | усі | 200: стан API і доступність БД |
| POST | `/auth/register` | усі | 201: користувач і JWT |
| POST | `/auth/login` | усі | 200: користувач і JWT |
| GET | `/auth/me` | користувач | 200: власний профіль |
| GET | `/categories` | усі | 200: категорії |
| GET | `/trainings` | усі | 200: каталог; необов’язковий `?category_id=1` |
| GET | `/trainings/:id` | усі | 200: одне тренування |
| POST | `/trainings` | admin | 201 і Location: нове тренування |
| PATCH | `/trainings/:id` | admin | 200: часткове редагування |
| DELETE | `/trainings/:id` | admin | 204: видалено, без тіла |
| GET | `/bookings` | користувач | 200: тільки власні записи |
| GET | `/bookings/:id` | власник | 200: власний запис |
| POST | `/bookings` | користувач | 201 і Location: новий запис |
| PATCH | `/bookings/:id` | власник | 200: часткове редагування |
| DELETE | `/bookings/:id` | власник | 204: видалено, без тіла |

Списки та ресурси: `{"data": [...]}` або `{"data": {...}}`. Для чужого запису API повертає 404, не розкриваючи його існування. Навіть адміністратор через `/bookings` бачить лише власні записи; роль admin керує каталогом.

## Приклади тіл запитів

Реєстрація `POST /auth/register`:

```json
{"name":"Дмитро","email":"dmytro@example.com","password":"Example-Password-123"}
```

Вхід `POST /auth/login`:

```json
{"email":"dmytro@example.com","password":"Example-Password-123"}
```

Успішна відповідь (токен тут скорочений):

```json
{"user":{"id":2,"name":"Дмитро","email":"dmytro@example.com","role":"member"},"token":"<JWT>","expires_in":3600}
```

Створення `POST /trainings`:

```json
{"category_id":1,"name":"Функціональне тренування","description":"Вправи на силу та координацію з тренером.","duration_minutes":50,"price_cents":35000,"image":"personal.png"}
```

Відповідь 201: `{"data":{"id":7,"category_id":1,"name":"Функціональне тренування","description":"Вправи на силу та координацію з тренером.","duration_minutes":50,"price_cents":35000,"image":"personal.png","created_at":"2026-11-10T12:00:00.000Z"}}`.
`GET /trainings` і `GET /trainings/:id` додатково повертають `category_name` через JOIN.
Редагування `PATCH /trainings/7`: `{"price_cents":36000}` → 200 з оновленим ресурсом.

Створення `POST /bookings` (поставте актуальну дату від сьогодні до року вперед):

```json
{"training_id":1,"session_date":"2026-11-20","phone":"+380671234567","note":"Перше заняття"}
```

Відповідь 201:

```json
{"data":{"id":1,"user_id":2,"training_id":1,"session_date":"2026-11-20","phone":"+380671234567","note":"Перше заняття","created_at":"2026-11-10T12:00:00.000Z","training_name":"Силове тренування","price_cents":25000,"duration_minutes":60}}
```

`PATCH /bookings/1`: `{"note":"Прийду за 10 хвилин"}` → 200 з оновленим ресурсом.
`DELETE /bookings/1` → 204. `DELETE /trainings/7` → 204, якщо тренування не має записів.

## Валідація та коди помилок

- 400: некоректний JSON, ID, невідомі поля, порожній PATCH, неправильні типи/межі.
- 401: відсутній/некоректний/прострочений JWT або неправильні дані входу.
- 403: учасник намагається змінити каталог.
- 404: ресурс відсутній або запис належить іншому користувачеві.
- 409: дубль email/назви/запису; FK не існує; видалення тренування з записами.
- 413: JSON більший за 16 КБ. 429: понад 50 спроб на auth-ендпоінтах за 15 хвилин з однієї IP-адреси.
- 500: внутрішня помилка, зокрема недоступність БД; стек і SQL клієнту не повертаються.

```json
{"error":{"message":"Перевірте заповнення полів.","fields":[{"field":"price_cents","message":"Too small: expected number to be >=0"}]}}
```

Ім’я: 2–80 символів. Email: нормалізація lower-case, до 254 символів. Пароль: від 12 символів, до 72 UTF-8 байтів (межа bcrypt). Публічна реєстрація завжди створює member, поле role не приймається.
Тренування: назва 2–100, опис 10–2000, тривалість 15–240 хвилин, ціна цілим числом копійок 0–1000000. Зображення — одне з шести локальних PNG.
Запис: реальна календарна дата в дозволеному діапазоні, телефон `+380` + 9 цифр, коментар до 300 символів. Один запис користувача на тренування на дату.

## Insomnia: ручна перевірка

1. Імпортуйте `docs/insomnia-collection.json` у **Local Vault**.
2. У Base Environment задайте `base_url`, власні `email`, `password`, актуальну `session_date`.
3. Надішліть реєстрацію / вхід. Скопіюйте отриманий JWT у `token`. Для admin увійдіть із даними `.env` та запишіть JWT в `admin_token`.
4. Виконайте створення тренування, перенесіть його числовий `id` у `training_id`. Перевірте GET і PATCH.
5. Створіть запис та перенесіть `id` у `booking_id`. Перевірте GET, PATCH, DELETE.
6. Видаліть створене тренування. Перевірте окремі запити 400/401/403/404.
7. Для 409 повторіть реєстрацію з тією самою поштою або той самий запис. Для перевірки власника створіть другого користувача та спробуйте прочитати/змінити чужий запис.

У репозиторії немає паролів чи робочих JWT. Колекція не містить автоматизованих тестів: вони належать до КП №3. `lab-report-2/screenshots/insomnia-*.png` — фактичні відповіді в Insomnia; `api-verification.json` — окремий журнал перевірочних HTTP-запитів під час розроблення.

## Безпека та межі версії

bcrypt cost 12; параметризовані SQL-запити; JWT HS256 з issuer/audience та строком дії; перевірка ролі та власника на сервері; FK/UNIQUE/CHECK у PostgreSQL; Helmet/CSP; body limit і auth rate limit. Сервер не зберігає таблицю сесій. Вихід видаляє JWT із sessionStorage браузера; вже виданий токен лишається чинним до завершення години. Для інтернет-розгортання потрібні HTTPS, власні секрети й захищений доступ до БД. Це навчальний сервіс: запис зберігається в БД, але оплат, SMS і погодинних слотів у цій роботі немає.
