# Баг-репорти та регресія

## BUG-001 — PATCH запису стирає примітку, якої не було у запиті

- **Короткий опис:** часткове оновлення телефону могло підставити типове `note: ""` і стерти наявну примітку.
- **Кроки відтворення:** створити запис із непорожньою приміткою; надіслати `PATCH /api/bookings/:id` тільки з новим `phone`; повторно отримати запис.
- **Очікуваний результат:** змінюється лише телефон, примітка зберігається.
- **Фактичний результат до виправлення:** примітка ставала порожньою через default у partial-схемі.
- **Критичність:** Major.
- **Виправлення:** для PATCH поле `note` перевизначено як optional до `.partial()`; default застосовується лише при POST.
- **Статус:** Fixed / Verified. Покрито API regression-тестом «PATCH ... зберігає поля, яких немає у запиті».

## BUG-002 — Сервер автоматично відкриває порт при імпорті в тест

- **Короткий опис:** початковий `server/index.js` запускав listener на верхньому рівні, тому Supertest не міг безпечно імпортувати Express app.
- **Кроки відтворення:** імпортувати `app` у тестовий файл; запустити набір паралельно із сервером.
- **Очікуваний результат:** тест отримує Express app без відкриття мережевого порту.
- **Фактичний результат до виправлення:** імпорт запускав сервер і міг завершитися `EADDRINUSE`.
- **Критичність:** Major.
- **Виправлення:** експортовано `app` і `startServer()`; listener запускається лише при прямому виконанні `server/index.js`.
- **Статус:** Fixed / Verified. 12 API-тестів виконуються через Supertest без listener.

## BUG-003 — Інструкція PostgreSQL містила неактуальні реквізити

- **Короткий опис:** команда документації використовувала `gym_user/gym_db`, тоді як Compose створює `ritm/ritm`.
- **Кроки відтворення:** виконати `docker compose exec db psql -U gym_user -d gym_db`.
- **Очікуваний результат:** відкривається psql.
- **Фактичний результат до виправлення:** `FATAL: role "gym_user" does not exist`.
- **Критичність:** Minor.
- **Виправлення:** README містить актуальну команду `docker compose exec db psql -U ritm -d ritm`, SQL-приклади і розділ частих помилок.
- **Статус:** Fixed / Verified.

Після виправлень виконано повну регресію: 24/24 автоматизованих і 9/9 ручних тестів Passed. Відкритих Critical/Major дефектів немає.
