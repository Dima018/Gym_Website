# База даних та 3НФ

Схема PostgreSQL: `database/schema.sql`. Імпортована у dbdiagram.io модель: `database/schema.dbml`. Готова ER-діаграма: `lab-report-2/er-diagram.svg` і `.png`.

| Сутність | Призначення | Ключі та зв’язки |
|---|---|---|
| users | Ім’я, нормалізована пошта, bcrypt-хеш, роль, час створення | PK id, UNIQUE email |
| categories | Назви напрямів | PK id, UNIQUE name |
| trainings | Каталог: назва, опис, тривалість, ціна в копійках, PNG | PK id, UNIQUE name, FK category_id → categories.id |
| bookings | Запис користувача на тренування на дату, контактний телефон, коментар | PK id, FK user_id → users.id, FK training_id → trainings.id, UNIQUE(user_id,training_id,session_date) |

Усі атрибути атомарні (1НФ). Таблиці мають сурогатний первинний ключ; неключові атрибути залежать від усього ключа, часткових залежностей немає (2НФ). Назва категорії не дублюється в trainings, ім’я/email користувача й назва/ціна тренування не дублюються в bookings; вони отримуються JOIN. Транзитивних залежностей неключових атрибутів немає (3НФ). Телефон є контактом конкретного запису і може відрізнятися для різних записів.

Зв’язки: categories 1:N trainings; users 1:N bookings; trainings 1:N bookings. Видалення батьківських записів обмежено ON DELETE RESTRICT. Ціни зберігаються цілими копійками без похибок float. Час created_at — timestamptz, дата заняття — date. Унікальний складений ключ запобігає дублюванню при одночасних запитах; індекси підтримують JOIN та вибірки власних записів.

GET відповіді містять поточну ціну тренування; окремого рахунку/історичної ціни замовлення в межах КП №2 немає. Початкові шість тренувань — seed-дані, які зберігаються у справжній БД та надалі редагуються через API.
